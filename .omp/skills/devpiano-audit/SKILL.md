# devpiano 全面代码质量审计

> 触发本 skill 后：对 devpiano 项目执行一次全面、可复核的代码质量审计，复制 `docs/audit/AUDIT-000-audit-template.md` 后填写 `docs/audit/AUDIT-XXX-code-quality-audit-<日期>.md`。**本报告第 8 章是唯一状态源**，第 0 章看板、结论与修复路线图必须与之对应。
> **只读审计**：不修改源码、ADR、既有文档或历史报告。仅允许新增本次审计报告、生成构建缓存及隔离的验证产物；修复另开迭代。

## 背景（必读）

- 项目定位与范围红线：`docs/reference/project-scope.md`
- 架构与技术栈：`docs/reference/architecture.md`
- 操作契约：`AGENTS.md`（§2 核心架构要求、§4 提交规范、§9 结束输出要求）
- 决策记录：`docs/decisions/` 全部 ADR（决策合规维度按模板 3.10 核对表逐条执行）
- 已知缺口：`docs/issues/known-issues.md`
- 路线图：`docs/roadmap/roadmap.md` + `docs/roadmap/current-iteration.md`

## 审计范围

- 实现范围：`source/**/*.cpp`、`source/**/*.h` 的当前实际清单，包含应用入口、`source/tests/` 和已内化的 `source/UI/jive/core/`。文件数量、模块职责和热点按本轮统计，不沿用历史报告结论。
- 测试范围：检查全部测试文件的编译接入、类别注册、默认选择、实际执行与消费者覆盖；不能因被过滤、未调用或只测 helper 就从清单排除。
- 只读契约/接线输入：现行 docs、ADR、构建配置和 scripts 可用于核对实现契约、门禁与目录边界；不扩展为脚本/配置或第三方实现的全面审计。当前契约描述错误登记 `DOC`，环境失败单列验证限制。
- 第三方边界：`submodules/` 下实现不审、不改，允许只读核实框架版本、API 签名和调用前提；内化代码不因其上游来源而被排除。

启动前记录提交、用户既有改动与实际文件清单；报告说明逐文件覆盖、切片负责人、未审部分和统计方法。按实际能力使用 codegraph、Context7、LSP；工具未挂载/索引不可用时先记录再按项目规则降级，截断清单和不完整引用不能证明全覆盖或没有调用者。可独立分片只读审查，门禁及运行验证由主审统一执行。

## 执行方法（按序）

1. **基线与平台门禁**（记录到模板 4.1）：
   - 默认流程以 [quickstart](../../../docs/guides/quickstart.md) 和 [WSL / Windows 工作流](../../../docs/guides/wsl-windows-msvc-workflow.md) 为准；先运行 `./scripts/dev.sh self-check` 并确认验证数据隔离。
   - WSL 主树默认仅用 `./scripts/dev.sh wsl-build --configure-only` 刷新编译数据库，不把 configure 成功记为软件构建通过。
   - 三闸门：`./scripts/dev.sh win-build` 完成镜像树 **Debug** 构建；按 quickstart 的 **Windows Debug 单元测试**流程配置、构建并执行镜像测试；`./scripts/dev.sh format --check` 检查零差异。报告填写实际命令、工作目录与执行范围，不将默认选择的测试称为全部已写测试。
   - 全面审计/迭代边界由主审统一执行一次 `./scripts/dev.sh tidy --all`，记录项目诊断与退出码；不可用时说明。禁止自动 `--fix`、逐文件例行检查及用 shell `source/**/*.cpp` 代替完整清单。
   - 完整 WSL 构建/测试仅在用户明确要求额外跨平台验证时执行，并说明与日常流程的区别；Release 不默认执行。
   - 结果按实际填写通过/失败/未执行/受限。命令 exit 0 不等于零警告、完整测试覆盖或消费者契约已验证；任一失败先定位记录，不在审计中修复。
   - 原命令失败与替代验证分开记录。缓存/工具路径坏时可使用同 preset 的隔离 Debug 构建树，不删除原缓存、不改源码/配置；替代成功不得覆盖原失败。
2. **全部 ADR 合规核对**（模板 3.10）：
   - 枚举 `docs/decisions/` 实际 ADR 并与索引核对，记录有效/废止/被替代及继承关系，不固定编号上限或表行数。
   - 每条先分离当前有效决策本体、当前事实描述和历史事实，再填写实现消费者、可执行检查、API 前提及未覆盖范围。有效决策用合规/部分合规/违反；证据不足用未验证，废止且本轮无适用规则用不适用，不冒充合规或违反。
   - 仅已确认的有效决策违反/部分合规登记 `CMPL`；事实描述错误按只读纪律登记 `DOC`，历史差异不自动成为问题。
   - 旧实现残留检查针对旧 API、SDK 类型、原生 include 和消费者调用；后端名称、注释、诊断输出本身不是违例，裸词 grep 零命中也不能单独证明合规。
3. **分领域审查**（模板 3.1~3.10）：保留 10 个领域，逐项给评级（A~D）、本轮结论与关联问题；既审模块，也追踪跨边界状态转换，如 NoteOn→改映射→NoteOff、加载/Editor→重扫/退出、旧 Take→新导入→保存、同步/防抖写入顺序。必须有可达消费者和反例，不凭类型、命名或历史结论预判缺陷。
4. **验证、证据与统计**：
   - 按实际填写 4.1 的平台、配置、完整命令、工作目录、退出码、覆盖及证据；不可用/受限项说明原因。4.2 分开统计文件/物理行、注册/默认执行套件、子测试和断言，不引用旧数字。
   - 验证程度与处理状态/优先级独立：运行确认、静态确认、推断待证。正式问题需运行反例或可复核的可达消费者/契约违反证据；仅推断候选留在第 8 章待证区，不计正式问题，不因未运行危险场景降低已确认风险级别。
   - 每个证据使用报告内稳定 `EVID-NNN`，按 4.4 保留基线/环境、前置条件、最小输入或代码、精确构建/运行命令或可复建配方、预期、实际输出和未验证范围。路径/版本可参数化，但必须说明取值与依赖；不能用 `...` 或将被删除的临时路径代替配方。
   - 先核实探针走生产工厂、真实映射/写出/状态路径，再归因项目缺陷；探针自身编译/前置错误单列，不算产品反例。声明离屏/拓扑/人为争用的范围，不能外推为桌面、真实插件或声卡毛刺已实测。
   - 清理临时程序/产物前将最小复现和关键输出嵌入报告，或引用明确可持久读取的证据；仅会话产物不作唯一依据。主审统一执行消费者冒烟，不新增永久测试或审计平台。
5. **问题总表与历史 ID**（模板第 8 章）：
   - 本轮新问题按 12 个领域前缀分别从 001 连续编号，完整身份为 `AUDIT-XXX:<PREFIX>-NNN`，报告内可简写；`EVID-NNN` 仅是本报告证据 ID，不参与问题编号。
   - 相同根因不因路径/表现不同重复登记；不同根因不因现象相同就合并。对照 known-issues 和历史报告：新反证重开保留原报告+原 ID（如 `AUDIT-002:THR-001`），列原结论、新可达证据和重开原因，不回写旧报告。
   - 仅复核已有问题放第 8 章已知项复核区：有原 ID 保留来源命名空间（如 `known-issues:ERR-002`），无原 ID 用文档路径+原标题锚+基线引用，不以长标题冒充本轮新编号；同项不能同时在正表和复核区计数。
   - 正式表区分新发现/历史重开/已知复核、验证程度、处理状态和证据/复审引用；纯推断另放待证区。第 0 章分别统计来源，再对已确认唯一项按优先级/状态汇总，不混入待证候选或重复引用。
6. **排期与交付自检**：
   - 保留 P0~P3 路线图：未处理/处理中列处理项，已缓解/已暂缓列复审时间与重开条件，已关闭不纳入未闭环集合。
   - 从第 8 章正式表与已知复核区提取全部非已关闭的完整 ID/来源锚，与第 5 章完整引用去重排序后用 `comm` 比较；实际记录缺失/多余及重复数，不能只检查本轮新编号。
   - 核对 0~8 章、10 个领域、12 个前缀、动态覆盖、报告引用、直接验证证据、原失败保留、隔离产物清理及源码/既有文档未越界修改；不创建新的审计平台。

## 纪律（硬性）

- **只读边界**：仅写本次新报告和隔离验证产物，不修源码、ADR、既有文档或历史报告，不执行自动修复、自动提交或破坏性缓存清理。审计前记录基线与用户既有改动，交付时核对越界变更；清理自有临时产物，不删除用户文件。
- **验证隔离**：执行门禁和探针前确认配置、日志与输出不会覆盖真实用户数据；无法安全隔离的项目标记受限，继续其余可达工作，不以全量测试通过掩盖跳过项。崩溃、OOM、慢插件强杀等实验只允许在可丢弃且有限制的环境中执行。
- **ADR 两类处理**：当前事实/契约描述被证伪 → 登记 `DOC` 并引用原文，另开迭代修订，不开 `CMPL`；实现违反当前有效决策本体 → 登记 `CMPL`。历史上成立、后来被取代的事实保留背景，不因不同于当前实现就改写原文或登记违例。
- **P0/P1 从严**：崩溃/数据损坏/音频毛刺无声/内存泄漏/线程安全缺陷 → P0~P1，不因"暂未触发"降级。
- **不夸大**：静态确认与运行确认分别记录；未观测的退出、性能、插件/硬件影响标 `[未验证]`，纯推断标 `[推断]` 并列明待证条件。测试数量、exit 0、一次不崩溃不能单独证明消费者契约或用于关闭已确认缺陷。
- **复审与文档分工**：原始发现证据保留，可在本次报告第 8 章更新状态并补充验证程度/证据/复审引用，不堆修复过程。第 7 章只追加复审记录，修复详情写实现迭代与 roadmap；已固化历史报告不改写，新的审计/复审使用接续报告并保留原问题身份。
- 提交规范按 AGENTS.md §4（docs 类型，单逻辑单提交）。

## 交付

- `docs/audit/AUDIT-XXX-code-quality-audit-<日期>.md`（完整报告 0~8 章，序号接续已有报告）
- 三闸门及静态检查的实际结果、覆盖/环境限制（4.1~4.3）；原失败、替代验证与单独补跑不相互覆盖
- 持久可复核的消费者证据（4.4）与尚未运行的 Windows/插件/声卡手工清单（4.5），明确前置条件及安全隔离；关键发现和建议下一步按第 8 章与路线图一致交付
