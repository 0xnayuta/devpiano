# ADR-015: 本地化完整消息模板与分类标点

## 状态

**已接受（2026-10-05）。**

本决策规定消息组织方式，不引入通用格式化器。现行机制与回归边界见 [国际化分册](../reference/features/internationalization.md)，实施状态和任务只在 [roadmap](../roadmap/roadmap.md) / [当前迭代](../roadmap/current-iteration.md) 维护。

## 背景

devpiano 使用 JUCE `LocalisedStrings` / `TRANS`、BinaryData 内嵌 `zh_CN.loc` 与英文原文回退。本决策提出时，缺词条导致的预设弹窗英文回退已经修复，但 `PresetFlowSupport` 仍将消息前缀、名称与后缀分别拼接，限制译文调整语序、引号、标点和空格。

需要分开处理两个问题：完整消息的可翻译性，以及本项目选择的中文文案风格。微软指南区分软件与文档的标点约定，不能据此宣称所有中文 UI 必须全部全角；也不能把正常的技术表达或用户数据混排判作错误。

当前主要需求是中英文界面和单名称参数。JUCE 已有字符串替换能力，没有必要仅为此引入另一套国际化框架或任意类型变参层。

## 决策

### 1. 保留已有语言与资源机制

- 保留 `LocalisedStrings` / `TRANS`、BinaryData 内嵌 `.loc`、运行时语言激活与英文原文回退。
- 英语使用 ASCII 原文消息键；中文文案在 `source/Locale/zh_CN.loc` 中维护。不改 `.loc` 解析格式、持久化语言标识、预设 UUID 或文件格式。
- 外部 `.loc` 仍是内嵌表缺键时的 fallback，不把它改成已有词条覆盖层。
- 业务调用处不通过语言分支或自动标点转换补救译文。

### 2. 自然语言使用完整消息模板

- 面向用户、有语法依赖的句子或短语必须作为完整翻译单元；其变量位置、引号、标点、空格和换行由模板控制。
- 首批单参数使用 ASCII 标记 `{0}`：先 `TRANS` 查表，再用 `juce::String::replace("{0}", value)` 插入值。不要先拼入名称再查表。
- 插入值只作为数据，不作为翻译键或格式串，不进行全半角转换、Unicode“美化”或二次解释。

本决策的单参数写法：

```cpp
auto message = TRANS("Delete preset \"{0}\"? This cannot be undone.").replace("{0}", name);
```

```text
"Delete preset \"{0}\"? This cannot be undone." = "确定删除演奏预设“{0}”？此操作无法撤销。"
```

### 3. 按内容分类选择标点

| 内容 | 项目约定 |
| --- | --- |
| 中文提示、确认、警告、说明句 | 默认采用中文 `，。？！：`；不机械保留英文句末空格。 |
| 消息中引用预设名、文件名等参数 | 中文模板默认采用弯引号 `“{0}”`；参数内部字符不改写。 |
| 标题、按钮与短标签 | 不为了整齐而机械添加句号；操作名与完整句子分别处理。 |
| 中文标签/选项后的圆括号夹注（含参数、缩写与快捷键） | 主体中文优先，统一采用中文全角圆括号 `（{0}）`；全角括号与前后汉字、西文、数字之间不添加空格。例如 `演奏者（近场展开）`、`室内乐厅（1.5 s）`、`十二平均律（12-EDO）`、`切换节拍器开关（Ctrl+M）`。 |
| 技术数字、单位、版本、快捷键、路径 | 保留表达自身的语法，例如 `0.6 s`、`12-EDO`、`2/4`、`48.0 kHz`、`Ctrl+S`。 |
| 用户名称、插件标识、路径等数据 | 保持原字符；既有业务准入/文件名规则不由本地化层改动。 |
| 独立西文短语内部自身标点 | 纯英文句子或未翻译技术串内部保留原有西文标点（如半角括号）。 |

这是 devpiano 的一致性约定，不宣称是唯一行业标准。不得做全局 ASCII → 全角转换。弯引号使用 `U+201C/U+201D`，不保证跨字体恒定占一个汉字宽度；圆括号遵循主体语言优先的全角括号 `U+FF08/U+FF09` 消除排版撕裂；长名称、换行、分隔边界和按钮布局必须通过实际 UI 检查。

### 4. 允许非语法性的技术拼接

不全面禁止 `+`。HTML/SVG 标记外壳、独立信息的分隔符与技术日志标签可以拼接；禁止的是通过拼接固定自然语言语序和标点的消息碎片。代码审查按语义区分，不按加号或半角字符是否出现一刀切。

### 5. 控制格式化复杂度

- 当前不引入通用 `locale::format()`、`std::format` / `std::vformat` 包装层、ICU、Fluent 或新语言支持。
- 不把单参数模式推广成 `.replace("{0}", a).replace("{1}", b)`：当 `a` 包含 `{1}` 时，后一次替换会改变已插入的用户数据。
- 清单中遇到现有多参数统计消息须单独评估，不能伪称项目不存在多参数需求；本小阶段只收口相关单参数消息。
- 确需多参数、复数/性别、日期/数字格式化时，按下方替代手续选择只解释原始模板的单次扫描或成熟格式化器。
- 当前 C++20 普通 `std::format` 不直接接受运行时 `TRANS` 结果；`std::vformat` 自 C++20 提供运行时格式路径，但需评估类型/编码适配、格式错误与维护成本，不是本阶段必需依赖。

### 6. 保持编码与实时边界

- C++ 源码与测试保持项目严格 7-bit ASCII 约束；中文译文和弯引号放 `.loc`，必需符号码点使用显式构造。避免把裸 UTF-8 字节交给 JUCE ASCII 构造入口，不把此约束宣称为全部编译警告的消除保证。
- 本地化查表、模板替换与 UI 文案生成限于 UI/非实时路径，不进入实时音频回调。英文回退不等于查表函数零锁或字符串生成零开销。

## 取舍与影响

- 完整模板允许译文控制语序与标点；代价是按完整句式维护词条，不能靠共用前后缀省翻译量。
- 单参数直接替换复用现有 `juce::String`，避免新框架及类型转换层；不提供通用复数、数字日期或多参数格式化。
- 字符风格和排版分开验收；资源正确不自动证明所有字体、长名称或原生窗口都显示正确。
- 既有消息需有序迁移，但不得在交付时留下同一消息的半迁移入口或兼容别名。

## 实施与验收

1. 建立实际调用清单：删除预设、另存/重命名/导入时的覆盖确认、成功提示及同类单参数自然语言；技术格式与多参数场景分列。
2. 迁移全部相关调用与 `.loc`，确认无引用后删除旧碎片键，不保留别名。源码不能用语言条件分支补标点。
3. 校验缺键、重复键、转义与占位符契约；外部缺键 fallback 与英文回退必须保留完整参数。字面量 `TRANS` 覆盖不等于全部 UI 已本地化。
4. 永久测试验证语言机制、回退、参数原样及消费者边界；只为不确定的边界保留必要回归，不钉具体中文措辞、模板源码或复制式自证。
5. 私有数据下运行真实窗口：中英双向、长名称、中文及 `{0}` / `{1}` / `%1` 等合法名称内容、确认/取消、UUID 与已有文件保护。已打开窗口是否重译按实际刷新能力记录，不把“创建时使用当前语言”冒称为所有窗口即时刷新。
6. 按项目 Windows 镜像 Debug 工作流验证，WSL 主树仅编辑/必要 configure；不主动 Release，不为本次文案迁移扩张音频或文件业务。

实施状态和任务只在 current-iteration / roadmap 维护，ADR 不作为另一份进度表。

## 替代与废弃条件

更激进方案必须新建后继 ADR，说明真实需求、候选方案、编译平台/编码/错误处理、实时边界、依赖影响与完整迁移验收。后继决策被接受时：

1. 将本 ADR 标记为“已由 ADR-0xx 替代”，双方建立链接，保留本决策的历史理由；
2. 后继 ADR 明确替代哪些规则及旧 `.loc`、调用点和回退的切换方式，不保留无必要兼容别名；
3. 迁移全部受影响调用并验证实际消费者后，才将后继方案列为已实现。

不得悄悄把本 ADR 扩写成另一种架构。WSL 额外产品构建或 Release 验证仍需用户明确要求，不作为本 ADR 自动附带的任务。
