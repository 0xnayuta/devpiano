## 2. 目标与非目标

### 2.1 目标

让相关自然语言消息的整句、参数位置、引号、问号、冒号和空格由 `.loc` 资源控制；参数仅作为原样数据插入。先收口预设删除/覆盖确认和相关成功提示，再按清单处理同类单参数自然语言消息。

### 2.2 非目标

- 不做全局 ASCII → 全角转换，不修改用户名称、路径、插件标识、技术单位、数字/版本/快捷键语法或持久化值。
- 不全面禁止技术字符串、标记外壳或独立信息分隔符的 `+`；禁止的是固定自然语言语序的碎片拼接。
- 不引入任意类型变参 `locale::format()`、新格式化框架、`std::format` / `std::vformat`、ICU、Fluent 或新语言。
- 不改预设 UUID、CRUD 确认/取消、覆盖事务、文件格式、音频事件时序、实时闭包或日志政策。
- 不启动 Phase 36/37；其进入条件及独立实机补验仍由 roadmap 管理。

## 3. 实施原则

1. **完整翻译单元**：自然语言句子/短语用完整 ASCII 英文消息键；所有属于该消息的标点、空格、换行留在模板中，译文可以调整语序。不要先拼入名称再调用 `TRANS`。
2. **最小替换**：本阶段单参数约定为 `{0}`，先 `TRANS` 查表，再使用 `juce::String::replace("{0}", value)`。插入值不得再被翻译、全半角转换或解释为模板。
3. **分类标点**：中文确认/说明句默认中文标点与弯引号；标题/按钮不机械补句号。技术表达保留自身语法。这里是本项目约定，不把微软或 CLREQ 描述成要求所有中文软件一律全角。
4. **切换完整**：迁移所有相关调用点，包括新建、重命名与导入时的覆盖确认；确认无引用后删除旧前后缀键及无用词条，不保留兼容别名。
5. **有限扩展**：清单遇到多参数统计/复数等真实需求时单独列出，不连续 `.replace` 重新解释插入值；需要改变 ADR-015 的轻量策略时先制定后继 ADR。不得因统一风格顺便重写所有状态栏/诊断系统。
6. **线程与编码**：消息生成只在 UI/非实时路径；C++ 源码与测试保持严格 7-bit ASCII，中文译文仅放 `.loc`，必需码点使用显式构造。
7. **测试约束**：永久测试验证语言机制、英文回退、参数原样与消费者行为，不硬钉具体中文措辞或复制模板文本作自证；一次性文案检查与截图可使用临时消费者。

## 5. 实施落地消息形态

已完成的代码写法与语言表条目（遵循 ADR-015）：

```cpp
auto message = TRANS("Delete preset \"{0}\"? This cannot be undone.").replace("{0}", name);
```

```text
"Delete preset \"{0}\"? This cannot be undone." = "确定删除演奏预设“{0}”？此操作无法撤销。"
```

字典检查应验证英文键、转义、重复键和占位符契约；具体中文文案可润色。不要把用户名称当格式字符串，也不要对同一插入结果接续处理其他参数标记。

## 7. 后续决策与独立风险

确有多语言语法、多个参数、复数/性别、日期/数字本地化等需求时，按 ADR-015 的替代手续提出后继 ADR，评估编码、错误处理、编译支持、实时边界和全部调用迁移；不得悄悄把轻量规则变成通用格式化框架。

AUDIT-004 的未关闭/已缓解项按其第 8 章与第 5 章复审；物理声卡与厂商/IME 补验按 §4.5 与 acceptance 实施，必要时由新证据重开原身份。它们不因当前任务切换而遗失，也不混入新的本地化消息问题编号。
