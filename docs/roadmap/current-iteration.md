## 1. 输入事实与实施边界

以下事实用于区分已有能力与新增任务，不替代现行特性契约：

- **频率与共鸣**：[TemperamentEngine](../../source/Audio/TemperamentEngine.h) 已有律制与 A4 换算；[Piano88KeyTable](../../source/Audio/Piano88KeyTable.h) 通过固定锚点插值提供逐键物理参数；[PianoSynthVoice](../../source/Audio/PianoSynthVoice.h) 将刚度因子作用于全部分音，第一分音也随之偏移。现有开放主弦交感池不等于独立的 Duplex 非发音弦段模型。
- **音色保存**：[PerformancePreset](../../source/Layout/PerformancePreset.h) 保存声学配置子集，不含 `brightness`、`hammerHardness`、`resonance` 等核心音色字段；[AcousticSnapshot](../../source/Audio/AcousticSnapshot.h) 才包含完整运行参数。风格选择、普通预设保存与 Take 快照的作用域必须明确。
- **踏板与键区**：[BuiltinSynthesiser](../../source/Audio/BuiltinSynthesiser.cpp) 已有逐通道 CC66 捕获与释放；电脑键盘和 ViewModel/UI 尚无完整入口。[KeyMapTypes](../../source/Core/KeyMapTypes.h) 的逐键通道与 [ChannelMatrix](../../source/Midi/ChannelMatrix.h) 可表达静态双区，但 KeyGroup 是全局互斥切换，组通道可覆盖逐键通道；[MainComponent](../../source/MainComponent.cpp) 的电脑键盘 CC64/67 回调目前固定发送至通道 1。
- **单音源端点**：[InstrumentEndpoint](../../source/Audio/InstrumentEndpoint.h)、[AudioEngine](../../source/Audio/AudioEngine.cpp) 与 [PluginOfflineRenderer](../../source/Recording/PluginOfflineRenderer.cpp) 当前均为内置/VST3 二选一。双层应在 Instrument 内部完整实现，不等于增加多插件槽位或通用路由图。
- **移调问题分流**：`1a3c99c`、`41972e3` 已修复并增加离线快照移调与 NoteOff 回归，不重新排为未修任务。键盘输入已映射后写入 Take、下游再消费快照移调的条件性重复变换另属事件语义问题，见 [路线 A 局限与路线 B 备忘](../issues/known-issues.md#原生演奏快照移调与-wav-音高不一致路线-a-已实施路线-b-重构备忘)。

实施遵守 [AGENTS.md §3.1](../../AGENTS.md#31-开发期减负与-yagni)、[项目边界](../reference/project-scope.md) 与 [架构契约](../reference/architecture.md)：保留增强模态模型路线、固定音频拓扑、NoteOff 原身份、采样级时序及产品自有实时契约；不以新功能为由推倒重写稳定模块。

## 2. Phase 37：物理建模调律与被动共鸣校准

目标：将调律、被动共鸣与钢琴风格建立在明确的频率语义、真实音频和可测实时成本上。不承诺与 Pianoteq 微观实现一致，也不宣称完成两项算法即可达到“声学巅峰”。

### Task 37-1：频率语义与声学基线

**实施内容**：

- 区分名义柔弦频率、实际第一分音、律制偏移、逐键拉伸、同音弦微失谐与毛毡老化扰动。A4 参考应对应关闭刻意微失谐时的实际第一分音基准，不要求有意失谐的每根同音弦都等于参考频率。
- 核对弦刚度、弦长、阻尼和模态参数的来源；已有插值锚点不冒充完整逐键实测。资料不能支持的琴型和拟真承诺不写成已标定事实。
- 使用生产渲染路径记录低、中、高音区及琴桥交界的分音、衰减、八度和复八度基线，说明采样率、力度、踏板、混响及微失谐条件。基线留在直接实施记录，不新建长期维护的研究平台。

**直接验收**：

- [ ] 频率语义和量测方法明确，包括单弦/中心弦基准与同音弦拍频的区分；实际渲染数据可复核，不用 getter 或生产公式回算证明声音正确。
- [ ] 记录当前基线及参数来源的可信边界；指标使用 Hz、cents、选定分音对的频差和衰减，不以主观形容词或测试数量验收。

### Task 37-2：受约束的八度拉伸调律

**实施内容**：

- 在内置 Piano 频率链路实现关闭与经过校准的默认拉伸，保持律制独立；Sine 基准与 VST3 的 MIDI 输入不自动套用钢琴拉伸。
- 基线目标约定为：

  $$f_m=m f_T(n)2^{s_n/1200}\sqrt{\frac{1+B_n m^2}{1+B_n}}$$

  其中 $m$ 从 1 开始，$f_T(n)$ 是律制与 A4 换算结果，$s_n$ 是逐键拉伸音分，$s_{69}=0$。此式定义关闭刻意微失谐时的基线；同音弦和老化扰动的叠加另行明确，不混入名义频率定义。
- 选择并记录不同音区的分音匹配策略与可接受误差，受现有 $B$ 曲线、A4 锚点及音高顺序约束。Railsback 作为校准参考，不复制一条通用曲线，也不承诺消除全部音程拍频。
- 同轮更新受频率语义改变影响的实际消费者和回归；不得仅改 getter 期望值而没有真实音频证据。

**直接验收**：

- [ ] 真实第一分音基准锚定 A4，保留 400.0–480.0 Hz 参考范围；拉伸关闭时符合新基线约定，历史律制保持独立有效。
- [ ] 代表性音区及选定八度/复八度指标符合明确的校准目标；邻键音高顺序和范围边界有效。关闭拉伸且 $B=0$ 时退化为律制基准的谐波列，不引入除零或残余调律偏移。
- [ ] 在常用采样率和受支持低采样率边界实际发声，保持 Nyquist 安全、有限输出和确定性；不通过改 MIDI 音符或全局 Pitch Bend 冒充逐键调律。

### Task 37-3：Duplex 非发音弦段被动共鸣

**实施内容**：

- 建模主弦发音长度之外的非发音弦段，明确频率、耦合、阻尼和衰减；由主弦能量激发，采用固定容量与有界处理成本。
- 与现有开放主弦交感分工明确；只调整受新增调律/共鸣影响的消费者，不将整套共鸣系统顺带推倒重写。
- 非发音弦段不以 CC64 或按键持有作为存在条件，但必须有有效激励才发声。核对 A4、律制与拉伸改变时的主弦/共鸣调谐关系，提供可旁路的声学控制。
- 本任务不建模 Blüthner 独立 Aliquot 第四弦，不用自由高频振荡、噪声或额外混响替代被动共鸣。

**直接验收**：

- [ ] 未踩踏板时也能被主弦激发；无激励不自激，关闭后可旁路，频率与衰减变化可从真实音频辨识。
- [ ] 长时间、多复音、采样率切换和参数边界下稳定，释放/Panic 后没有持续残留，尾音结束可观察。
- [ ] 与现有交感和主混响组合不会重复计入能量；产品自有新增路径保持无锁、零堆分配与零库函数三角调用，增量成本实际测量。

### Task 37-4：可保存的钢琴风格预设

**实施内容**：

- 补齐风格实际需要的核心音色、拉伸和 Duplex 字段，沿用现有预设/快照及提交机制，不另建音色文件格式或完整琴型工厂。
- 提供少量经真实音频与受控试听区分的参数化风格，例如明亮、温润、近场或复古取向；不以现有宏观旋钮宣称完成 Upright、Honky-tonk 或 Fortepiano 物理结构复刻。
- 一键风格选择只提交其声学作用域，不意外替换键位、切换插件或覆盖全局调号；风格声学字段与 Master/其他独立参数的边界明确，普通演奏预设的既有映射职责不被取消。

**直接验收**：

- [ ] 保存、重启、重新选择后实际音色和新声学控制有效恢复，不仅验证名称或字段回读。
- [ ] 切换风格不污染输入映射或插件状态，不破坏已发音身份；音量匹配后的试听和音频分析能说明预设差异。
- [ ] 当前格式缺省字段遵守明确默认值；保存/加载失败保持原文件与当前会话，不引入历史迁移、旧字段别名或双路径。

### Task 37-5：实时、录制与离线集成

**实施内容**：

- 将新声学状态贯通设置、普通预设、AcousticSnapshot、Take 内嵌快照、实时执行及内置 WAV；继续按采样偏移执行同块参数切换，不在 UI 重算 DSP 状态。
- 在真实声音路径验证参数切换、NoteOff 原身份、共享 Master/Reverb 和尾音。现有 WAV 固定 2.0 秒尾音窗口继续作为截断边界，不承诺全部自然尾音。
- 统一执行本阶段 Windows Debug 构建、相关既有回归、消费者冒烟和迭代边界门禁，只同步直接受影响的现行契约与简短 changelog。

**直接验收**：

- [ ] 同一 Take 在实时与内置 WAV 中执行一致的参数和事件语义，同采样参数变更后的起音有效，持续音释放不被后续配置改写。
- [ ] 实际波形/WAV 和可见声学 UI 经过验证；正常保存/加载、当前格式拒绝及失败/取消文件保护有效。
- [ ] 分配/锁/三角调用与 callback 成本有直接证据；沿用现行内置性能验收范围，不将第三方插件或特定硬件效果外推为通过。

## 3. Phase 38：电脑键盘分区、三踏板控制与固定双层演奏

目标：把已有逐键通道、矩阵与踏板核心转化为完整的电脑键盘演奏体验。双层限定为同一规范输入驱动内置 Piano 与一个当前 VST3，复合发声仍属于 Instrument 内部。

### Task 38-1：输入、录制与回放变换契约

**实施内容**：

- 明确区域、Group、修饰键、矩阵和全局移调的作用顺序与一次性边界，记录 Take 中音符身份的含义以及回放/WAV/MIDI 导出的消费方式。
- 优先沿用现有已映射事件录制边界，消除已烘焙音高被再次按快照移调的路径；不默认启动全链路 Raw Key Note 重构。标准 MIDI 导出表达最终发声音高，不导出物理键位替代音符。
- 保持 NoteOn 锁定、NoteOff 使用原身份，以及同音最后持有者/FIFO 释放规则；音高、通道、力度和静音优先级不各自建立第二套变换。
- 如果事件语义变更要求格式准入变化，同轮明确当前版本与全部读写消费者；拒绝不支持格式时保护原文件和会话，不保留旧义兼容路径。

**直接验收**：

- [ ] 真实键盘录制后，现场演奏、原生回放、WAV 与 MIDI 导出的音高/通道满足同一已明确的身份契约，无重复移调或重复矩阵路由；覆盖矩阵关闭/启用、不同跟随掩码与通道 10 的边界。
- [ ] 起音后改变全局调号、Group、Alt、矩阵或跟随掩码，松键仍释放原身份；静音绑定保持静音，同音持有与重复起音有效。
- [ ] MIDI 导入、当前格式保存/加载及拒绝保护回归有效；已有 `1a3c99c`/`41972e3` 的离线身份防线不被绕过。

### Task 38-2：Sostenuto 与多区域踏板闭环

**实施内容**：

- 复用已有 CC66 捕获与释放核心，确定不冲突的电脑键盘触发入口，补齐应用接线和 ViewModel/UI 状态，不恢复外部 MIDI 硬件支持。
- 核对 CC66 Up→Down 捕获语义及重复高值幂等性：不能在踏板已踩下后重新捕获新起音。重复捕获是当前静态分析需验证的边界，不将其写成已运行确认或已修复。
- 明确 CC64/66/67 作用的实际输出通道和仍持有身份；切区、切组或变更通道后，抬踏板须清理原目标，不能只向新目标发 Off。双层时控制器按端点分发，不重复统计物理输入。
- 明确 CC64/66 交互、Panic、失焦、停止、暂停、Seek 和 A/B 回跳清理/恢复；失焦仅清理现场输入，不打断文件回放。Seek 继续遵守不追溯重放历史 NoteOn 的既有契约，控制器状态恢复不冒充旧捕获音符集合恢复。

**直接验收**：

- [ ] 踩下前仍按住的音被保持，踩下后的新音不被捕获；重复高值、释放顺序、同采样事件及逐通道隔离有效。捕获声部被抢占后，新分配声部不继承旧音的 CC66 捕获状态。
- [ ] CC64/66 组合、多区域实际输出通道与原持有通道均正确；录制收尾和上述 Transport/焦点边界没有悬挂或残留踏板状态。
- [ ] 实际键盘触发、可见踏板指示、录制/文件/MIDI/WAV 消费者有效；第三方控制器实现差异与未测厂商单列。

### Task 38-3：双手物理键区编辑与显示

**实施内容**：

- 按稳定 keyCode 定义两个区域，提供区域级通道、半音移调与八度的批量配置，尽量落到既有逐键绑定与 ChannelMatrix，不增加通用区域路由引擎。
- 明确区域与 Group 的优先级、继承和覆盖规则；Group 仍是全局切组，不把 Group A/B 分别变成左右手运行实例。启用双区必须显式处理组通道对逐键通道的覆盖。
- 区域身份在物理输入阶段确定，不随后续移调跨过某个 MIDI 音高阈值而换区；不默认扩展成 MIDI 文件按音高分流的另一套 Split Point 功能。
- QWERTY 与虚拟钢琴消费同一最终 ViewModel，提供区域标识和配置反馈，保留逐键标签/颜色及鼠标配置输入身份；UI 不二次计算映射。

**直接验收**：

- [ ] 两区可同时演奏并独立配置通道、移调和八度，实际声音与双看板投影一致。
- [ ] 按住键后切区、切组、修改区域参数或矩阵，再松键仍释放原身份；两区同输出音的最后持有者规则有效。
- [ ] 实际区域编辑、鼠标演奏、窄窗口与焦点路径有效，不破坏逐键定制、Shift/Alt、静音绑定或踏板目标。

### Task 38-4：固定 Piano + 单 VST3 双层发声

**实施内容**：

- 两个固定端点消费同一规范输入音高/通道，保留单音源演奏方式；不在输入层人为产生两次物理 NoteOn，也不默认把 MidiChannelMapper 或 HeldKeyIdentity 泛化为 1→N。
- 使用 prepare 阶段预分配的音频和必要的 MIDI 工作缓冲分别渲染、混音，防止后一层覆盖前一层或插件修改 MIDI 污染另一层。混音后只经过一次公共 Master/Reverb 链，插件输出 MIDI 不回灌主输入。
- 提供必要的层开关与增益配比；处理插件报告延迟与内置声部的采样对齐，保持有界成本，不用 Sleep 或物理时钟补偿。
- 按音频块/既有停 callback 边界处理模式切换、层禁用、插件卸载、重建和重扫，释放原端点持有状态，不把旧 NoteOff 发给新实例，也不在启用新层时凭空重发仍按住的键。
- 不增加每层独立移调、通道、任意键区或多插件槽位；不使用全局 Pitch Bend 强行让 VST3 跟随 Piano 逐键拉伸，使用者可按需要关闭钢琴拉伸。

**直接验收**：

- [ ] 两层均真实发声，输入事件采样时序一致，增益配比有效，混音不覆盖且主效果不重复；力度估算、和弦与 Sync Pedal 不把一次击键统计两遍。
- [ ] 两层松键/Panic、模式和层开关、插件卸载/重建/重扫及设备准备边界无悬挂、误释放新实例或失效指针。
- [ ] 非零插件报告延迟的对齐经消费者验证；产品自有实时路径无锁零分配，第三方 JUCE VST3 框架限制与插件内部行为分别记录。

### Task 38-5：双层状态与录制/导出/UI 闭环

**实施内容**：

- 保存层模式与配比并纳入有效演奏快照；区域配置沿用其已明确的输入/录制语义，不在回放中重新套用物理键区变换。
- 实时和 WAV 均实现固定两层复合渲染，沿用独立离线 VST3 实例、共享事件/参数边界及事务写出与协作取消，不只让实时路径发声。
- 延续原生文件不捆绑 VST3 二进制、插件身份或内部状态的外部依赖边界；按相同可用插件与明确状态验证双层导出，不承诺换机或插件改变后还原录制时的厂商音色。
- 双层导出缺少插件或离线实例创建失败时明确失败并保留原目标，不能静默只导出钢琴却宣称双层已还原；不顺带改动单音源的既有降级范围。
- 检查实际层状态 UI、电脑键盘与鼠标、插件 Editor、并行试听/导出、取消、设备重建及应用退出。永久 UI 测试仍使用纯内存闭包。

**直接验收**：

- [ ] 保存/加载后层模式与配比有效；在相同插件及明确状态下，真实实时输出和 WAV 都包含两层，事件身份、参数边界和 Master 处理符合契约。
- [ ] 缺失插件、创建失败、渲染/写入失败及协作取消均明确反馈并保护原目标；退出等待实际 worker 结束，不强杀第三方处理。
- [ ] 上述实际 UI/Editor/录制/导出生命周期组合有直接证据，未测硬件或厂商组合不勾选通过，第三方音频不承诺逐比特一致。

## 5. 验证纪律与文档维护

- **验证与风险成比例**：永久回归聚焦真实音高/声学边界、NoteOff 身份、CC66 捕获、采样时序、数值安全、生命周期和当前格式文件/会话保护。复用已有防线，不新建通用测试平台，不重新钉住声明值、译文、简单转发或字段回读。
- **声音与性能证据**：使用生产渲染、可读 WAV、受控音量试听和实际分配/锁/callback 观测；音频有限不等于零分配，字段存在不等于参数已影响声音，既有测量不证明新增 DSP 成本。
- **平台门禁**：每阶段集成后统一执行 `./scripts/dev.sh format --check`、`./scripts/dev.sh win-build` 和 Windows 镜像树 Debug 默认 CTest（命令及前置见 [quickstart](../guides/quickstart.md)），并运行上述受影响消费者；全量 clang-tidy 只在迭代边界执行。WSL 仅编辑和必要 configure，不在本地运行 Linux 软件测试，不主动执行 Release。
- **实际 UI 与测试边界**：实际表面必须观察；永久 UI 测试继续遵守 [ADR-016](../decisions/ADR-016-headless-safe-pure-in-memory-ui-testing-pattern.md)，不创建原生顶层窗口，不以 headless 跳过。真实声卡和厂商补验沿用 [现行验收边界](../reference/acceptance.md)，不因阶段交付而自动认证。
- **最小文档同步**：任务勾选仅在代码和直接消费者完成后更新；只同步直接受影响的 [内置音源](../reference/features/builtin-piano-synthesis.md)、[键盘映射](../reference/features/keyboard-mapping.md)、[预设](../reference/features/performance-presets.md)、[录制回放](../reference/features/recording-playback.md)、[原生文件](../reference/features/performance-persistence.md)、[离线渲染](../reference/features/plugin-offline-rendering.md) 契约与简短 changelog。阶段状态仍只在 roadmap 维护，完成记录归档后不回写历史。
