## 1. 输入事实与实施边界

### 现有能力与本轮增量

以下只区分已有能力与待实施增量，不替代现行特性契约：

| 领域 | 输入基线中的能力 | Phase 39 增量边界 |
|---|---|---|
| 频率与参数表 | [PianoTuning](../../source/Audio/PianoTuning.h) 已归一化第一分音并实现 A4 锚定和分音匹配拉伸；[Piano88KeyTable](../../source/Audio/Piano88KeyTable.h) 为模型锚点插值 | 复核参数来源、量测与可靠的刚度锚点，不退回未归一化频率或通用 Railsback 曲线 |
| 琴槌与整音 | [PianoSynthVoice](../../source/Audio/PianoSynthVoice.h) 已有力度相关有效硬度、接触时间、击弦点陷波及瞬态核 | 将单硬度控制深化为可校准的三力度整音，保留增强模态激振路线，不重复建设打击模块 |
| 衰减与同音 | 已有多弦振荡器、微失谐及快/慢振幅包络 | 本轮记录其声音基线；耦合、辐射与双阶段能量模型留给后继阶段 |
| 微观动力学 | 已有一阶指数趋近的 Blooming 和力度触发的短时 Pitch Glide | 不把已有机制误写成缺失，不在本轮叠加新的张力或绽放效果 |
| 共鸣与踏板 | 已有音板模态、十二音级交感池、被动 Duplex 及逐通道 CC64/66/67 | 校准频率时复核相关调谐；不推倒共鸣、踏板或声部所有权 |
| 保存与消费者 | [AcousticSnapshot](../../source/Audio/AcousticSnapshot.h)、[PerformancePreset](../../source/Layout/PerformancePreset.h)、Take 与实时/两个 WAV 路径已有共同消费边界 | 同轮迁移受影响的配置和实际消费者，不只扩展结构体或修改字段回读测试 |

实施遵守 [AGENTS.md §3.1](../../AGENTS.md#31-开发期减负与-yagni)、[项目边界](../reference/project-scope.md) 与 [架构契约](../reference/architecture.md)：固定 `Performance Input -> Instrument -> Master -> Output`，不改已保存的最终 MIDI 身份、原 NoteOff、采样级排序或产品自有实时契约。普通预设的音乐配置与本机键区模式仍分离，固定 Piano + 当前单 VST3 不扩展为多槽位或通用路由图。

### 外部研究输入与证据准入

`pianoteq9` 是独立研究仓库，其 `README.md`、`SUMMARY.md`、声学基准报告、Phase 1–5 规格书及保留 WAV 是候选研究输入，不是 devpiano 的运行或默认测试依赖。只吸收有来源的参数语义、可公开解释的方程和独立量测目标；不搬运反编译控制流、专有结构、商业二进制或音色资源。Clean-Room 声明不替代具体来源、独立推导与许可核对。

已识别的输入风险应在 Task 39-1 中复核，而非直接变成默认常数：

- 自动化脚本入口目前只打印初始化信息，未执行其宣称的完整 MIDI 生成、无头渲染与拟合链路；保留 WAV 的存在不等于流程可复现。
- 建议的指数 `B(k)` 曲线与报告锚点不一致，琴键序号和 MIDI 编号存在混用风险；C7 拟合频率与保留 WAV 谱峰的对应关系需要重新确认。
- 输出包络上升时间不能等同于琴槌接触时间或软件延迟；三力度高频占比变化不能唯一反推出毛毡接触指数。
- 正交静态投影不等于有效的同音能量耦合；振幅、功率、能量权重及其衰减时间常数必须区分。
- 研究 C++ 示例中的逐采样库函数三角调用及历史兼容建议不符合现行产品契约，不能原样移植。

不以报告的 Accepted、拟合优度、主观形容词或测试数量代替可复核证据。未经准入的结果继续标为假设；可信资料不足时保留明确标注的模型常量，不虚构全琴逐键实测或特定型号复刻。

## 2. Phase 39：可复核声学基线与三力度整音校准

目标：先取得可靠的频率、频谱和时间域输入，再在现有增强模态音源内实现连续力度整音，并完成状态、真实声音及实时成本闭环。不承诺复制 Pianoteq 微观实现或商业预设音色。

### Task 39-1：研究结论准入与统一量测口径

**实施内容**：

- 将引用结论区分为参数语义证据、黑盒观察、理论推导和工程假设，记录来源、目标版本、预设及实际生效的控制条件。外部软件输出不冒充真实钢琴直接测量。
- 统一 `midiNote` 与 `pianoKey = midiNote - 20` 的语义，覆盖 MIDI 21–108；区分柔弦频率、实际第一分音、中心弦、同音混合峰、律制、拉伸和刻意微失谐。
- 核对保留 WAV 与输入 MIDI 的对应关系，明确样本格式、采样率、NoteOn/Off、力度、持音长度、踏板、混响、后级 EQ、拾音及增益。无法确认的条件标为未知，不假定全部为纯干音。
- 用 Windows 生产 `BuiltinSynthesiser` / `PianoSynthVoice` 和现有渲染消费者建立 devpiano 对照；先覆盖 C1–C7、A0/A4/C8 及 G2/G#2 交界，三力度使用 MIDI 41/70/98。代表音量测成立后再扩展逐键扫描。
- 说明分音拾取、时间窗、包络定义、噪声底、分辨能力、归一化及残差；留出未参与拟合的音高或力度作独立检验。复算使用保留数据与小范围分析，不扩建通用研究平台，也不要求 CI 安装商业软件。
- 基线及复算输入留在本任务实施记录；大体积或专有资产不进入仓库。记录版本、输入摘要、文件散列和必要命令，以区别同名但条件不同的产物。

**直接验收**：

- [ ] 同一保留音频可独立复算选定谱峰与包络，结果说明窗口、分音编号、残差及不确定性；最强混合峰不冒称中心弦，较高 `R²` 不代替正确的分音识别。
- [ ] 当前生产声音基线、参数可信边界及外部参考对应条件可复核；频率、响度、归一化频谱和衰减分开记录，不以生产公式副本或 getter 证明声音正确。
- [ ] C7 频率、建议 `B(k)` 曲线、起振/接触时间及幅度/能量解释的疑点有明确准入或不采用结论；未复核数据没有进入默认模型或通过声明。

### Task 39-2：受证据约束的逐键非谐性校准

**实施内容**：

- 只按 Task 39-1 已准入的可靠锚点调整刚度 `B`，保留音区和琴桥交界的物理解释；测量不足区域继续明确标为模型插值，不用一条未经验证的指数曲线覆盖全琴。
- 保持现行第一分音归一化与 A4 锚点：

  $$f_m=m f_1(n)\sqrt{\frac{1+B_n m^2}{1+B_n}},\qquad f_1(n)=f_T(n)2^{s_n/1200},\quad s_{69}=0$$

  其中 $m$ 从 1 开始，$f_T$ 为律制/A4 名义频率；同音弦和老化扰动在基准之外叠加。参考报告使用柔弦 $f_0$ 的拟合必须先换算语义，不能直接当第一分音输入。
- 同轮复核逐键拉伸、分音匹配、Duplex 段频率和开放弦共鸣的调谐，不只修改 `Piano88KeyTable`。校准仍独立于 MIDI 音符身份，Sine 与 VST3 不自动套用钢琴拉伸。
- 在修改前固定选定分音/音程的误差指标和可接受界限，使用未参与拟合的声音检验；没有足够证据的键位不以补齐“实测表”为验收目的。

**直接验收**：

- [ ] 可靠锚点与留出声音的分音误差符合事先约定的指标；插值及模型假设范围明确，没有伪造逐键或琴型标定。
- [ ] 实际 A4 400.0–480.0 Hz 锚点、选定八度/复八度、邻键音高顺序及原已起音身份有效；拉伸关闭且 `B=0` 的谐波极限不退化。
- [ ] 8000/44100/48000 Hz 的真实发声、有限性、Nyquist 安全及超界 Duplex 旁路有效；实际共鸣与主弦调谐不出现未说明的错位或残留。

### Task 39-3：连续三力度琴槌整音

**实施内容**：

- 在现有模态激振内引入 Piano/Mezzo/Forte 整音配置，以 41/70/98 为对照锚点，定义力度 1–127 的连续插值、端点及合法参数范围；不机械复制研究幂指数或全琴统一高频增益。
- 明确三锚点调节量与基准力度响应的关系，默认锚点相同也不能误消除现有力度相关音色；主硬度旋钮只作为同一有效模型的整音宏控制，不保留旧 DSP 分支作为兼容回退。
- 区分响度映射、有效硬度、接触时间及分音频谱，明确 Brightness、毛毡老化、击弦点陷波和 CC67 的作用顺序，不重复计入同一增益或硬化效果。
- 先在代表音实现和校准，再检查音区及分音数交界；必要的小型算法模块仅放在 `source/Audio/`，不引入第二套声部、完整 Verlet 接触求解器或通用参数框架。
- 用幅度归一化的频谱观察音色，用原始峰值/RMS 观察响度，分别校准；参考场景的 `+12.12 dB` 不作为全琴统一门槛，`32.2 ms` 不直接写入 ADSR 或延迟目标。

**直接验收**：

- [ ] 真实声音证明三个锚点可控，代表音的相邻力度与锚点两侧无突跳，端点和合法极值下弱奏不凭空消失、强奏不产生非有限输出或未说明的增益爆发。
- [ ] 归一化频谱与响度曲线分别符合校准目标，并由留出力度验证；不以单次更响、字段回读或参考公式副本宣称音色改善。
- [ ] Brightness、老化及逐通道 CC67 组合有效；参数变化不重新定位持续音的频率/通道身份，新起音按新整音执行，偷声部或重用不继承旧激振状态。

### Task 39-4：状态、预设与真实渲染闭环

**实施内容**：

- 同轮贯通 `AcousticSnapshot`、Settings、Performance Preset、Take 内嵌快照、实时、内置 WAV 和固定双层 WAV，保留采样点参数提交与同采样 NoteOn 的既有排序。
- 普通预设继续只恢复其音乐/声学作用域，不额外保存插件实例、Master/ADSR、音源选择或本机分区模式；新整音字段只作用于内置 Piano，不向 VST3 注入物理参数。
- 更新现有五种声学风格、Custom 判定和必要的声明式设置控件，主窗保持简洁。仅暴露已有真实声音作用的参数，不将主观名称或未标定的琴型写成物理复刻。
- 在实施中明确当前字段单位、范围、默认及省略行为。若替换单硬度字段改变文件语义，同轮更新当前版本及全部读写方并拒绝旧义，不留旧字段别名、迁移链或并行声学模型；正常可选字段默认与首次启动不当成历史兼容删除。
- 保存/加载/取消失败继续保护原文件与会话；录制的最终 MIDI 身份不重套键区、Group、矩阵或快照移调。固定双层仍经过一次公共 Master/Reverb，缺失必需插件不能静默只导出钢琴。

**直接验收**：

- [ ] 保存、重启、重新选择风格及同一 Take 回放后，新整音的实际声音有效恢复；音量匹配后的风格差异可解释，不只检查字段往返。
- [ ] 同采样快照/NoteOn、持续音原身份释放和非零 wet 的生产实时/内置 WAV 对照有效；固定双层输出保留层增益、插件独立状态与既有采样延迟对齐。
- [ ] 实际中英文设置表面、窄窗、主控同步和关闭生命周期已观察；当前格式准入、非法数据、失败/取消保护及普通预设作用域保持有效。

### Task 39-5：受控试听、实时成本与阶段集成

**实施内容**：

- 复用 `PianoSynthVoiceTest`、`PianoTuningAndDuplexTest`、`PianoSnapshotWavParityTest`、踏板/柔音及相关文件、双层回归；仅为可信的新边界补永久用例，删除直接受影响的声明、文案或实现细节 oracle，不重新钉住参数锚点。
- Windows Debug 实际运行受影响的生产发声、保存/回放、WAV 和 UI，使用同一 MIDI、对齐条件及受控音量试听；播放链路成功不等于主观优好或特定真琴认证。
- 在完整 callback 闭包观察新增成本，包含起音、快照、参数边界、密集输入、多复音、Panic、偷声部和采样率重新准备；分配、锁、库函数三角观察器需有已知正调用自检，初始化单列。
- 保持产品自有零锁、零堆分配、零库函数三角及有界状态；测量同配置改动前后增量和 callback 时长，不用只计振荡循环或测试数量代替整体实时证据。
- 集成后统一执行 Windows Debug 构建、默认 CTest、格式检查及迭代边界全量 tidy，只同步直接受影响的现行契约和简短 changelog。8 复音单核 CPU ≤0.7% 的长期目标单独认证，不因 Debug 观察改写目标或声称通过。

**直接验收**：

- [ ] 受控生成、播放、真实 UI 与文件/回放/WAV 消费者已运行，声音变化与保留范围可解释；测试之外有直接生产行为证据。
- [ ] 完整新增路径的分配/锁/库三角及同配置成本有可复核记录；长时、多复音和参数边界下无自激、非有限输出或悬挂，Panic 与重用完整结束旧状态。
- [ ] Windows Debug app/tests、默认完整 CTest、`format --check` 与迭代边界 `tidy --all` 已执行；用户文件无副作用，临时消费者与产物归属明确，未验证硬件/厂商和 CPU SLA 不勾选通过。

## 4. 验证纪律与文档维护

- **证据先于承诺**：先选定窗、指标、条件与误差界限，再实施和检验；改动后的结果不能反向决定通过门槛。参考输出只证明所测模型/条件，不认证商业微观机理、全琴常数或真实型号。
- **回归与风险成比例**：复用音乐身份、采样时序、数值稳定、生命周期和文件/会话保护防线；不新建通用声学平台，不用生产公式副本、字段存在、文案或测试数量验收声音。
- **平台门禁**：WSL 仅编辑和必要 configure；构建、软件测试及原生消费者在 Windows 镜像树 Debug 执行，命令及前置见 [quickstart](../guides/quickstart.md)。默认不发起 Release，优化构建的 CPU 认证需另行明确安排；全量 clang-tidy 只在迭代边界执行。
- **UI 与测试边界**：实际表面需观察；永久自动化 UI 测试遵守 [ADR-016](../decisions/ADR-016-headless-safe-pure-in-memory-ui-testing-pattern.md)，纯内存离屏、显式消息泵，不创建原生顶层窗口或跳过 headless。商业软件和原生窗口只用于独立消费者，不成为默认回归依赖。
- **尾音与外部依赖**：现有 WAV 固定 2.0 秒尾音截断不自动扩展；慢衰减基线使用足够长的持音而非截断尾部拟合。物理声卡、rollover/IME/DPI、商业 VST3 和跨机音色沿用 [现行验收边界](../reference/acceptance.md)，文档提交不构成补验。
- **最小同步**：新能力实现后才写入 [内置音源](../reference/features/builtin-piano-synthesis.md)、[预设](../reference/features/performance-presets.md)、[原生文件](../reference/features/performance-persistence.md)、[录制回放](../reference/features/recording-playback.md) 与 [离线渲染](../reference/features/plugin-offline-rendering.md) 的现行契约；本页只维护直接任务证据，项目状态和长期顺序以 roadmap 为准。已归档的 Phase 37/38 和历史审计不回写。
